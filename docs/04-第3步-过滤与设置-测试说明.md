# 第 3 步：过滤与设置（测试说明）

本步交付：关键词 / 正则 / 用户屏蔽、“仅显示”模式（如只看同传）、合并短时间内的重复弹幕（×N）、悬浮窗内长按弹幕快速屏蔽、过滤计数。

> 过滤引擎、重复合并、规则存取都是纯 Kotlin，新增 12 个单元测试，连同之前的共 47 个，在我这边全部通过。界面部分仍需你编译后实测。

---

## 一、入口

- 首页 →「过滤规则（屏蔽 / 仅显示 / 合并重复）」
- 悬浮窗里**长按某条弹幕** → 底部出现操作栏：「屏蔽此用户」「屏蔽这句」「取消」（8 秒不操作自动收起；锁定状态下不可用）
- 「隐藏直播间表情」开关仍在「悬浮窗样式 → 弹幕内容」

## 二、规则说明

| 规则 | 匹配方式 | 作用范围 |
|---|---|---|
| 关键词 | 弹幕文字**包含**该词即命中，不区分大小写 | 屏蔽：普通弹幕、醒目留言、礼物、进场 |
| 正则 | Java 正则，在文字中**查找**（不要求整句匹配）；不区分大小写写 `(?i)` 开头 | 同上 |
| 用户 | 与 UID、用户名或（第 4 步）视频弹幕发送者 hash **完全相等** | 同上 |
| 仅显示模式 | 打开后，普通弹幕只显示命中“仅显示”规则的 | 只作用于普通弹幕 |

- 屏蔽规则优先于“仅显示”规则。
- 系统提示（已连接、断线重连等）永远显示。
- 新增屏蔽规则后，悬浮窗里已显示的匹配弹幕会被移除；关闭/删除规则不会把已移除的恢复。
- 合并重复：从某条弹幕**第一次出现**起的时间窗口内（默认 10 秒，可调 3～60 秒），内容相同（忽略大小写、首尾空格）的弹幕不新增一行，而是把第一条末尾的 ×N 加一；超过窗口后重新计数。

## 三、测试清单

| # | 操作 | 预期 |
|---|---|---|
| 1 | 用**模拟弹幕 50/秒**，添加关键词“哈哈” | 含“哈哈”的弹幕不再出现；已显示的也被移除；过滤页“本次连接已过滤 N 条”在增长 |
| 2 | 添加正则 `^\d+$` | 纯数字弹幕（如“666”）被屏蔽，“666 好”不受影响 |
| 3 | 输入错误正则，如 `([` | 输入框标红提示“正则有误”，“添加”按钮不可点 |
| 4 | 规则右侧开关关掉 / 点“删除” | 该规则立即失效 |
| 5 | 打开“仅显示模式”，添加仅显示关键词“【同传】” | 模拟弹幕中只剩带【同传】的（以及系统提示） |
| 6 | 打开“仅显示模式”但不加任何规则 | 页面红字提示；普通弹幕全部不显示 |
| 7 | 打开“合并重复弹幕”，模拟 50/秒 | 重复内容（如“666”“草”）只出现一行，末尾 ×N 递增 |
| 8 | 悬浮窗里长按一条弹幕 → 屏蔽这句 | 提示“已屏蔽：…”，该内容消失，过滤规则页出现对应关键词 |
| 9 | 连直播间，长按一条弹幕 → 屏蔽此用户 | 未登录时名字是打码的（如“张**”），操作栏会提示“会同时屏蔽所有同样打码名字的用户” |
| 10 | 关闭应用重新打开 | 所有规则和开关都保留 |
| 11 | 直播间里实际使用：屏蔽几个常见刷屏词、开合并重复 | 观感是否改善；有无明显卡顿 |

## 四、已知限制

- **按用户屏蔽在未登录时不精确**：B 站对未登录连接把昵称打码、UID 置 0，本应用拿不到真实身份，只能按打码后的名字屏蔽，会误伤同样打码的其他人。这是未登录的限制；要精确按用户屏蔽只能登录（你之前选择了不做登录）。
- 正则由 Java 引擎执行，极端复杂的正则在大流量下可能拖慢处理，建议写简单的。
- 合并只在“最近 300 条”范围内更新 ×N；若第一条已被挤出列表，后面的重复会被计数但看不到。
- 规则只按文字匹配，不识别谐音、拆字等变体。
