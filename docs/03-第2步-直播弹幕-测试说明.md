# 第 2 步：直播弹幕（测试说明）

本步交付：输入直播间号 / 链接 / 分享文字 → 连接 B 站直播信息流 → 弹幕实时出现在悬浮窗；断线自动重连；WiFi ↔ 流量切换后自动恢复；支持从 B 站 App 分享启动；新增“连接日志”页。

> 我的环境仍然连不上 B 站和 Maven，所以**接口没有经过实际联网测试**。纯 Kotlin 部分（WBI 签名、数据包编解码、brotli/zlib 解压、消息解析、链接解析）有 27 个单元测试，在我这边全部通过；其中 WBI 用了公开文档里的测试向量，INTERACT_WORD_V2 和醒目留言/礼物用了真实消息样本。

## 二、测试清单

| # | 操作 | 预期 |
|---|---|---|
| 1 | 首页“直播弹幕”输入一个**正在直播**的房间号（选个热门的），点“连接” | 标题栏依次显示“正在获取直播间…”→“获取弹幕服务器…”→“连接中…”→“房间标题 · 已连接”；列表先出现几条历史弹幕和“—— 以上是最近的历史弹幕 ——”，然后实时弹幕开始滚动 |
| 2 | 同时打开 B 站 App 看同一个直播间，对照 1～2 分钟 | 弹幕内容基本一致；用户名显示为打码形式（如“张**”）属于正常（未登录限制） |
| 3 | 输入完整链接 `https://live.bilibili.com/房间号` | 同上 |
| 4 | 输入短号（带短号的大主播，例如房间页 URL 里是 3～4 位数字的） | 能正确连上 |
| 5 | 在 B 站 App 直播间点“分享”→ 找“更多/系统分享”→ 选“弹幕机” | 本应用自动启动悬浮窗并退回 B 站；如果 B 站分享面板里没有系统分享入口，改用“复制链接”，再回本应用点“粘贴”→“连接” |
| 6 | 样式页打开“醒目留言”“礼物”“进场与互动” | 对应消息开始出现（需要直播间里有人送礼/发 SC） |
| 7 | 连接状态下关闭 WiFi（切到流量），再打开 WiFi | 列表出现“网络已切换，正在重连”，几秒内“已重新连接” |
| 8 | 开飞行模式 30 秒再关闭 | 标题栏显示“等待网络…”，恢复网络后自动重连 |
| 9 | 连接后切到 B 站 App 看 30 分钟以上 | 一直有弹幕；如中途断开，应能自动重连（列表里会有“连接断开…/已重新连接”提示） |
| 10 | 输入一个**未开播**的房间 | 提示“主播当前未开播”，仍保持连接 |
| 11 | 输入一个不存在的房间号（如 999999999999） | 提示“直播间 … 获取失败：B站接口错误 …” |
| 12 | 输入视频链接 | 提示“识别到视频 …，视频弹幕将在第 4 步实现” |
| 13 | 连着一个直播间时输入另一个房间号点“切换到此直播间” | 列表清空，切换到新房间 |
| 14 | 首页 → 连接日志 | 能看到连接过程；有问题时点“复制”发给我 |

**有任何一项不符合预期，请把“连接日志”复制给我**，并说明是第几项。

## 三、本步的已知限制与不确定点

- **未登录**：B 站对未登录连接会把他人昵称打码、UID 变成 0，并下发“为保护用户隐私，未登录无法查看他人昵称”提示（已查证：blivedm 源码注释、bilibili-API-collect 存档）。存档里提到部分房间豁免。未登录时弹幕**数量**是否被限制，我没找到证据，需要你对照 B 站 App 观察（测试项 2）。
- **getDanmuInfo 失败时的降级**：会改连默认服务器、不带 token（blivedm 的做法）。这种情况下现在还能不能收到弹幕，我不确定；日志里会出现“降级”字样。
- **分享入口**：B 站 App 分享面板里是否有“系统分享/更多”入口、分享出来的文字格式，我没法实测。已兼容“文字里带 b23.tv 短链”和“带 live.bilibili.com 链接”两种情况。
- **被系统杀掉后不会自动恢复**：仍是 `START_NOT_STICKY`。如果你的手机经常杀后台，按“权限与后台保活”页设置；如果设置后仍被杀，告诉我，再考虑做“被杀后自动重连”。
- 弹幕里的表情（如 `[dog]`）目前显示为文字，不显示图片。

## 四、本步新增的代码

```
data/bili/                      ← 接口层（B 站协议只出现在这里）
├─ BiliHttp.kt      OkHttp、统一 UA、CookieJar（只持久化 buvid3/buvid4）
├─ BiliAuth.kt      buvid3 获取、WBI 密钥缓存与刷新
├─ Wbi.kt           WBI 签名算法（纯函数）
├─ BiliClient.kt    依赖容器
├─ proto/ProtoReader.kt        极简 protobuf 解码
├─ live/LiveRoomApi.kt         get_info / getDanmuInfo / gethistory
├─ live/LivePacketCodec.kt     WebSocket 包头、brotli/zlib 解压、分包
├─ live/LiveCommandParser.kt   cmd → DanmakuItem
└─ link/LinkParser.kt, LinkResolver.kt   房间号/链接/短链解析
source/LiveDanmakuSource.kt     连接、认证、心跳、重连、网络切换
source/InputDanmakuSource.kt    解析输入后分派到直播（以后加视频）
util/NetworkMonitor.kt          监听默认网络变化
util/DebugLog.kt                连接日志
ui/LogScreen.kt                 连接日志页
```

重连策略：退避 1s → 2s → 4s … 最长 30s，连上后重置；每失败 3 次（或服务器数）重新获取 token；认证失败立即重新获取；35 秒收不到任何数据判定掉线（与 blivedm 相同）；默认网络变化立即重连。
